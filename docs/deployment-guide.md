# Production Deployment & Debugging Guide

This document contains the complete step-by-step deployment instructions for Phase 5, along with the root-cause diagnosis and resolution for the Render backend deployment error.

---

## 1. Diagnosis of Backend Deployment Failure (`backend.logs`)

### The Error in `backend.logs`
```text
2026-09-09T19:04:09.325565608Z ==> Running 'npm run start -w @ipk/api'
2026-09-09T19:04:11.528132689Z > start
2026-09-09T19:04:11.52816933Z > tsx src/server.ts
2026-09-09T19:04:11.55004632Z sh: 1: tsx: not found
2026-09-09T19:04:11.626884842Z npm error Lifecycle script `start` failed with error:
2026-09-09T19:04:11.628455349Z npm error code 127
2026-09-09T19:04:11.633340023Z npm error command sh -c tsx src/server.ts
2026-09-09T19:04:13.171942811Z ==> Exited with status 127
```

### Root Cause
1. In Render, setting the environment variable `NODE_ENV=production` causes `npm install` to omit `devDependencies` by default (`--omit=dev`).
2. Previously, `tsx` was listed in `devDependencies` in `apps/api/package.json` and root `package.json`.
3. Consequently, `npm install` during Render's build phase did **not** install `tsx` into `node_modules/.bin`.
4. When Render attempted to start the server via `npm run start -w @ipk/api` (`tsx src/server.ts`), the Linux environment failed with **Exit Code 127 (`tsx: not found`)**.

### Fix Applied
1. Moved `"tsx": "^4.19.2"` to `dependencies` (production dependencies) in both `apps/api/package.json` and root `package.json`.
2. Updated `package-lock.json` via `npm install`.
3. Now, whenever `npm install` runs under `NODE_ENV=production`, `tsx` is guaranteed to be installed and available to execute `src/server.ts`.

## 2. Diagnosis of Frontend Vercel Deployment Failure

### The Error in Vercel Build Logs
```text
00:42:25.298 Running "next build"
00:42:26.169  ⚠ Installing TypeScript as it was not found while loading "next.config.ts".
00:42:27.106 Installing devDependencies (yarn):
00:42:27.106 - typescript@5.8.2
00:42:27.278 yarn add v1.22.19
00:42:27.318 warning package-lock.json found. Your project contains lock files generated by tools other than Yarn...
00:42:27.364 warning Missing version in workspace at "/vercel/path0/apps/api", ignoring.
00:42:27.367 warning Missing version in workspace at "/vercel/path0/apps/web", ignoring.
00:42:27.382 error An unexpected error occurred: "Cannot read properties of undefined (reading 'manifest')".
00:42:27.398  ⨯ Failed to load next.config.ts
00:42:27.435 Error: Command "next build" exited with 1
```

### Root Cause
1. **Missing `typescript` in `apps/web/package.json`**: `typescript` was only defined in root `package.json` under `devDependencies`. When Next.js evaluated `next.config.ts`, it did not find TypeScript in `apps/web`'s dependency tree.
2. **Next.js Fallback Installer Triggered**: Because TypeScript was missing, Next.js attempted to automatically install it using the system's global Yarn binary (`yarn add --dev typescript`).
3. **Workspaces without Version**: Because `apps/api` and `apps/web` did not declare `"version": "1.0.0"`, Yarn crashed when reading the workspace manifests.

### Fix Applied
1. **Added `typescript` and `@types/node` directly to `apps/web/package.json`** under `dependencies` and `devDependencies`.
2. **Standardized Next.js Config**: Converted `apps/web/next.config.ts` to `apps/web/next.config.mjs` so Next.js does not require TypeScript just to parse its configuration file.
3. **Added Workspace Versions**: Set `"version": "1.0.0"` in `apps/web/package.json`, `apps/api/package.json`, and root `package.json`.
4. Verified that `next build` completes in ~1.3s with zero errors or fallback installation attempts.

## 3. Step-by-Step Deployment Guide

Deploy the system in this exact order: **Database** &rarr; **API** &rarr; **Frontend** &rarr; **CORS Loop**.

### Step 1: MongoDB Atlas (Database)

1. Log into [MongoDB Atlas](https://www.mongodb.com/cloud/atlas).
2. Create a free **M0 cluster** (e.g. Frankfurt or US-East).
3. **Database Access**: Create a database user (e.g. `ipk_admin`) with a secure password.
4. **Network Access**: Add IP Address `0.0.0.0/0` (Allow access from anywhere).
   > **Note:** Render's free tier uses dynamic egress IPs that change regularly, so an open CIDR `0.0.0.0/0` is necessary on the free tier.
5. **Connection String**: Click **Connect** &rarr; **Drivers** &rarr; copy the URI:
   ```text
   mongodb+srv://ipk_admin:<password>@cluster0.xxxx.mongodb.net/ipk?retryWrites=true&w=majority
   ```
   *(Ensure the database name `/ipk` is in the path before query parameters).*

---

### Step 2: Render (Backend Express API)

1. Go to [Render Dashboard](https://dashboard.render.com).
2. Click **New +** &rarr; **Web Service** and select your GitHub repository.
3. Configure the service:
   - **Name**: `interview-prep-kit-api`
   - **Region**: Same or nearest region to your MongoDB Atlas cluster
   - **Root Directory**: `.` *(leave empty / root; do NOT set to `apps/api` because this is an npm workspace)*
   - **Runtime**: `Node`
   - **Build Command**: `npm install`
   - **Start Command**: `npm run start -w @ipk/api`
   - **Instance Type**: `Free`
4. Under **Advanced**:
   - **Health Check Path**: `/api/health`
5. Configure **Environment Variables**:
   | Key | Value | Purpose |
   |---|---|---|
   | `NODE_ENV` | `production` | Enables secure cookies (`sameSite: none`) & SSRF filters |
   | `MONGODB_URI` | `mongodb+srv://...` | MongoDB Atlas connection string |
   | `JWT_SECRET` | *(run `openssl rand -hex 32`)* | Signing secret for session JWT cookies |
   | `GEMINI_API_KEY` | `AIza...` | Google AI Studio API key |
   | `GEMINI_MODEL` | `gemini-3.6-flash` | Model identifier |
   | `WEB_ORIGIN` | `http://localhost:3000` | *Temporary placeholder until Step 3* |

6. Click **Deploy Web Service** (or trigger a manual deploy if already created).
7. Test the health endpoint once deployed:
   ```bash
   curl -s https://<your-render-api-name>.onrender.com/api/health
   ```
   **Expected Response:**
   ```json
   {"ok":true,"database":"connected"}
   ```
   *(If `database` is `"disconnected"`, check MongoDB Atlas user credentials and Network Access).*

---

### Step 3: Vercel (Next.js Frontend)

1. Go to [Vercel Dashboard](https://vercel.com).
2. Click **Add New...** &rarr; **Project** and import your repository.
3. In the project configuration:
   - **Framework Preset**: `Next.js`
   - **Root Directory**: Click **Edit** and choose `apps/web`.
   - **Build & Output Settings**: Leave defaults (`next build`).
4. Configure **Environment Variables**:
   | Key | Value |
   |---|---|
   | `NEXT_PUBLIC_API_URL` | `https://<your-render-api-name>.onrender.com` *(no trailing slash)* |
5. Click **Deploy**.
6. Save your public Vercel production URL (e.g. `https://interview-prep-kit.vercel.app`).

---

### Step 4: Close the CORS Loop (Crucial)

Browser cross-origin requests and credentials (cookies) require the API to explicitly allow the exact frontend domain:

1. Return to [Render Dashboard](https://dashboard.render.com) &rarr; your API Web Service &rarr; **Environment**.
2. Update `WEB_ORIGIN` to your Vercel production URL (without trailing slash):
   ```text
   WEB_ORIGIN=https://interview-prep-kit.vercel.app
   ```
   *(If you want Vercel preview deployments to work as well, add them comma-separated, e.g. `https://interview-prep-kit.vercel.app,https://interview-prep-kit-git-main.vercel.app`)*.
3. Save changes. Render will automatically redeploy the API.

## 3. Post-Deployment Verification

### 1. Cross-Origin Session Cookie Check
1. Open your Vercel URL in your browser.
2. Register a new account.
3. Open Chrome DevTools &rarr; **Application** &rarr; **Cookies** &rarr; your API domain.
4. Verify the `token` cookie is present with:
   - `HttpOnly`: checked
   - `Secure`: checked
   - `SameSite`: `None`
5. Refresh the page &rarr; verify you remain logged in.

### 2. Live Generation Verification
1. Create a kit with a real job description and target company website (e.g., 5 days).
2. Verify the live pipeline steps advance in real-time.
3. Inspect the kit upon completion:
   - Company brief and breakdown.
   - Categorized questions (Technical, Behavioral, etc.).
   - Interactive 3D flashcards (test flipping and space bar shortcuts).
   - Day-by-day study schedule.

### 3. Builder & State Model Test
1. Edit a question's prompt inline &rarr; badge changes to `Edited`.
2. Pin a question &rarr; badge changes to `Pinned`.
3. Click **Regenerate** for Technical &rarr; confirmation modal confirms preserved items.
4. Confirm edited and pinned questions are preserved while generated ones are refreshed.

### 4. Edge Cases Check
- **2-line job description**: Displays the `thin` description banner without inventing fake requirements.
- **Unreachable company URL**: Continues processing from the JD alone with an honest warning in the brief.
